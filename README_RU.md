# PlutoSDR: передатчик и приёмник RGB / текста

Два отдельных GUI-приложения на Python:

- `transmitter.py` — настройка и однократная передача всех пакетов выбранного изображения или текста; после последнего пакета передача данных заканчивается.
- `receiver.py` — настройка, загрузка эталона, непрерывный приём до Stop, восстановление RGB/текста, BER/PER/SNR-оценка, сохранение результатов.

Распакуйте **всю папку**: оба приложения используют общие `modem.py`, `session.py`, `radio.py`, `gui.py`. Запускать можно на разных компьютерах, каждый со своим Pluto. На одном компьютере у двух Pluto должны быть разные URI. Эти программы не общаются между собой по TCP/UDP: данные идут через радиоканал Pluto.

## Что взято из приложенной модели

Из `radio_lab_sim_rgb(2).py` сохранены RGB-пакеты 16×16×3 = 768 байт, заполнение краевых блоков нулями, CRC32, показ повреждённых пикселей при CRC-ошибке и серый цвет 128 для потерянных блоков. Передаются декодированные RGB-байты, а не содержимое PNG/JPEG-файла. Изображение не уменьшается. EXIF-ориентация применяется; альфа-канал отбрасывается. Для текста используется UTF-8, разбиение по 768 байт; граница пакета может проходить внутри UTF-8-символа, декодирование выполняется после сборки.

Это радиомодем с реальным вызовом `adi.Pluto.tx()` / `rx()`, а не подстановка вероятностных ошибок из симулятора. **В среде разработки не было PlutoSDR: аппаратный тракт и GUI на Windows ещё требуют проверки на вашем стенде.** При отсутствии драйвера или устройства приложение выводит ошибку, не переключается незаметно на симуляцию.

## Установка на Windows

Python 3.11/3.12 x64. Для GUI нужен Tkinter. Самый короткий путь при наличии Conda/Miniforge:

```powershell
conda create -n pluto-lab -c conda-forge python=3.11 numpy scipy pillow tk pyadi-iio libiio pylibiio
conda activate pluto-lab
cd C:\path\to\pluto_link
python transmitter.py
```

На принимающем компьютере:

```powershell
conda activate pluto-lab
cd C:\path\to\pluto_link
python receiver.py
```

Альтернатива — обычный Python и pip:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe transmitter.py
.\.venv\Scripts\python.exe receiver.py
```

Для варианта pip **дополнительно установите нативную библиотеку libiio x64** с совместимыми Python bindings и драйверы Pluto. Одного `pip install` недостаточно для установки нативной libiio. Путь к её DLL должен быть доступен загрузчику Windows. Не устанавливайте посторонний пакет с именем `iio` вместо `pylibiio`. Официальная инструкция ADI: [Quick Start](https://analogdevicesinc.github.io/pyadi-iio/guides/quick.html). Нативные сборки: [libiio releases](https://github.com/analogdevicesinc/libiio/releases).

При USB-подключении Pluto часто доступен через виртуальную сеть по `ip:192.168.2.1`; это URI для libiio, **не COM-порт последовательной консоли**. Если адрес у вашего Pluto другой, укажите его в поле URI. Для USB-backend можно использовать URI, полученный при сканировании контекстов:

```powershell
python -c "import iio; print(iio.scan_contexts())"
python -c "import adi; p=adi.Pluto(uri='ip:192.168.2.1'); print(p.sample_rate)"
```

Не запускайте проверочную команду одновременно с работающим приложением на том же SDR.

## Первый запуск

1. На RX выберите модуляцию, частоту центра, sample rate, преамбулу и CP. Эти пять настроек должны совпадать с TX.
2. Выберите **тот же** PNG/JPG или введите **точно тот же** текст. Совпадение эталона проверяется по 128-битному префиксу SHA-256 декодированных данных, размерам и типу. Эталон не передаётся в демодулятор и не используется для восстановления/исправления принятых битов.
3. Укажите папку результатов и нажмите **Start RX**. Дождитесь подключения в логе.
4. На TX выберите данные и нажмите **Передать один раз**.
5. Приёмник показывает результат по мере получения пакетов. После END он продолжает слушать; можно выполнить новую передачу. **Stop** завершает приём и сохраняет текущий результат, включая неполный.

Начальные настройки: BPSK, 1 MS/s, преамбула включена, CP выключен, TX gain −30 dB, RX gain 20 dB. Значение 2400 МГц в поле — исходное значение интерфейса, а не проверка условий использования частоты. Для кабельного стенда используйте аттенюатор с подходящим ослаблением между TX и RX.

Для первой проверки подойдёт небольшой файл `example.png` из комплекта (128×128, 64 RGB-пакета) или `example.txt`. Большое изображение передаётся заметно дольше: RGB занимает width×height×3 байта и не сжимается.

## Модуляции и физический сигнал

| Выбор | Реализация полезных данных | Бит/символ |
|---|---|---:|
| ASK / OOK | Два уровня: 0 и √2 | 1 |
| 2-FSK | Два ортогональных тона, некогерентное сравнение модулей корреляторов | 1 |
| BPSK | Две фазы | 1 |
| QPSK | Четыре фазы, Gray | 2 |
| 8-PSK | Восемь фаз, Gray | 3 |
| QAM-4 | Квадрат 2×2, Gray | 2 |
| QAM-8 | Прямоугольник 4×2, Gray | 3 |
| QAM-16 | Квадрат 4×4, Gray | 4 |

QAM-4/8/16 — степени двойки в диапазоне 4…16; QAM-8 здесь явно прямоугольная, не cross-QAM. QPSK и QAM-4 эквивалентны по геометрии нормированного созвездия, но имеют разные правила назначения битовых меток.

Это **одна несущая**, не OFDM. 8 комплексных отсчётов на символ; Rs=125 ксимв/с при Fs=1 MS/s. Символы прямоугольные, без RRC-фильтра. Полезная скорость зависит от модуляции и служебных полей. Полоса не равна только Rs; FSK шире PSK. Для FSK тона расположены на ±Fs/8 относительно выбранной частоты центра (при 1 MS/s: ±125 кГц).

Чтобы DC-коррекция AD936x не подавляла постоянную составляющую OOK, используется цифровая промежуточная частота Fs/4. Реальный LO Pluto = указанная частота центра − Fs/4. Приёмник переносит сигнал обратно цифровым смесителем. GUI показывает именно центр передаваемого сигнала.

Диапазон поля центра ограничен 326…3800 МГц; расширение диапазона штатного Pluto не требуется. Sample rate: 1 или 2 MS/s. RX работает с ручным усилением, чтобы быстрый AGC не менял пороги ASK внутри пакета.

### Пакет и переключатели

Пакет: `[необязательная BPSK-преамбула] [64-битный маркер заголовка] [защищённый BPSK-заголовок] [полезные данные + CRC32]`.

- **Преамбула:** отдельные 256 известных BPSK-символов. При включении поиск начала использует преамбулу; без неё — известный маркер заголовка. Отключение преамбулы действительно убирает её из TX, но не убирает обязательные поля формата пакета.
- **Заголовок:** версия, тип, модуляция, флаги, ID передачи, номер пакета, общее число пакетов, размер данных, размеры RGB, длина полезных данных, хеш эталона, CRC32 заголовка. Биты заголовка повторяются трижды, решение большинством. Полезные данные FEC не имеют.
- **Пилоты:** каждые 128 символов данных предваряются 32 известными символами для оценки фазы, частоты и усиления. Пилоты являются частью блоковой структуры и остаются при выключенной преамбуле. Для FSK используются известные тоны, для остальных — BPSK-пилоты.
- **Циклический префикс:** копия последних 16 символов каждого блока `пилоты + 128 символов данных`, добавленная перед этим блоком. RX удаляет её. Для линейных модуляций полезных данных при CP включён SC-FDE: 9-отсчётная LS-оценка канала по пилотам и регуляризованная частотная эквализация. Для FSK CP служит защитным интервалом; частотный эквалайзер не используется. Заголовок декодируется по пилотам без SC-FDE.
- **Whitening:** обратимое перемешивание байтов XOR-последовательностью, чтобы одинаковые пиксели не создавали длинные последовательности нулей. Это не шифрование и не исправление ошибок. Метрики считаются после обратного преобразования.

Преамбула и CP включаются **независимо**: можно оба, один или ни одного. CP не заменяет синхронизацию. Эквалайзер не гарантирует работу при произвольной многолучёвости; его модель и длина ограничены.

Пакет имеет фиксированную физическую длину для выбранных параметров. Заголовок не может заставить приёмник выделить произвольный объём памяти: предусмотрены проверки размеров. Ограничения: 32 MiB декодированных данных, 65536 пакетов, размеры RGB до 65535 по каждой оси.

### Завершение TX и работа RX

Все пакеты полезных данных передаются **по одному разу**, без ACK/повторов. Затем идут три служебных END-пакета, нулевой буфер для завершения очереди, уничтожение TX-буфера и минимальный TX gain. `tx_cyclic_buffer=False`: бесконечного повторения нет. Stop на TX отменяет оставшиеся пакеты; уже передаваемый буфер может завершиться.

RX собирает поток через произвольные границы IQ-буферов, ищет CFO в заданном диапазоне, проверяет CRC заголовка и отслеживает передачу по ID. Первый экземпляр пакета учитывается один раз; дубликаты не улучшают BER. В каждый момент отображается одна передача; при появлении нового ID предыдущая сохраняется. Чередующиеся передачи нескольких независимых TX одновременно не поддерживаются.

При переполнении очереди обработки IQ показывается счётчик потерь буферов и сбрасывается синхронизация. Такие потери могут повлиять на PER; программа не выдаёт их за чисто радиоканальные потери. Предел задержки Stop зависит от драйвера; таймаут libiio установлен в 2 секунды.

## BER, PER и SNR

### BER и отличие от симулятора

`BER = число отличающихся payload-бит / число сравниваемых payload-бит`.

Сравниваются все принятые пакеты с валидным заголовком, **включая CRC BAD**. Заголовок, преамбула, пилоты, CRC и PHY-padding в BER не входят. Для RGB нулевой padding краевых 16×16-блоков входит, как в исходной модели. Для текста PHY-дополнение последнего пакета не входит.

Симулятор знает ошибки даже пакета с потерянной синхронизацией. Реальный RX не знает демодулированные биты такого пакета. Поэтому:

- LOST не подменяется выдуманными ошибочными битами и не входит в знаменатель BER.
- Рядом выводится **покрытие BER**: доля ожидаемых payload-бит, которые удалось сравнить.
- При отсутствии совпадающего эталона BER и SNR показываются как `—` / JSON `null`. CRC/PER и восстановление работают без эталона.
- Если ни один заголовок не принят, факт и ID передачи не установлены: приложение не придумывает PER=1 только на основании тишины.

### PER

`PER = (N_expected − N_GOOD) / N_expected`.

GOOD означает принятый пакет с валидными заголовком и CRC полезных данных. Таким образом, PER включает CRC BAD и отсутствующие пакеты, в том числе первый и последний. Общее число пакетов передаётся в **каждом** заголовке, а не определяется максимальным принятым seq. END в знаменатель не входит.

До END/Stop значение предварительное: неполученные пакеты ещё могут прибыть. После END или Stop оно помечается итоговым. Если TX отменён раньше конца, оставшиеся запланированные пакеты считаются отсутствующими — это показатель завершённости всей попытки, не изолированный PER радиоканала.

Точно разделить LOST на «не поймали преамбулу» и «сломался заголовок» во всех случаях нельзя. В отчёт не подставляются SYNC/HEADER-статусы из симулятора. Счётчик неудачных кандидатов заголовка не является числом потерянных пакетов.

### SNR-оценка

`SNR_est = 10 log10(Σ|s_ref|² / Σ|z_rx − s_ref|²)`.

`s_ref` — символы независимо выбранного эталона после того же отображения битов. `z_rx` — принятые символы **до жёсткого решения**, после коррекции по пилотам/эквализации. Для FSK сравниваются комплексные выходы двух корреляторов с эталонными векторами `[1,0]` / `[0,1]`.

Считаются только полные символы payload; CRC и заполнение PHY исключены. Приёмник не подгоняет канал по эталонному payload: оценка канала использует только служебные пилоты. Ошибка включает шум, остаточную частотную/фазовую ошибку и искажения канала. Это **оценка качества в точке решения**, не поверенное измерение RF SNR и не Eb/N0. Между разными демодуляторами её нужно сравнивать с учётом различий наблюдений, особенно FSK. При большом числе потерянных пакетов она относится лишь к принятой части.

В текущей реализации фиксированы Rs и средняя энергия символа для равновероятных меток. **Равное Eb/N0 для разных модуляций автоматически не обеспечивается**, в отличие от программного канала исходного симулятора. Для эксперимента фиксируйте усиления, sample rate, геометрию стенда и указывайте, что сравниваете одинаковую Rs/уровень TX, а не одинаковую энергию бита.

## Результаты

Автоматически создаётся папка `received/transfer_<ID>/`:

- `received.png` — восстановленный RGB: CRC BAD видны, LOST серые.
- Либо `received.bin` и `received.txt` — фактические байты и UTF-8-представление с заменой невалидных символов. Места потерь заполнены нулевыми байтами; карта потерь — в CSV. В GUI нули показываются как □.
- `metrics.json` — BER, PER, покрытие, SNR-оценка, метаданные, дубликаты и потери IQ-буферов.
- `packets.csv` — по одному ряду на ожидаемый пакет: GOOD / CRC / LOST и число ошибок, если оно измеримо. Для потерянного пакета число ошибок пустое.

Приёмник никогда не заполняет потерянные пиксели из эталона.

## Проверки и ограничения

```powershell
python -m unittest discover -s . -p "test_*.py" -v
```

Тесты не требуют Pluto или libiio: покрыты все 8 модуляций × оба состояния CP × оба состояния преамбулы, произвольные границы потока, шум, фазовый/частотный сдвиг, фильтрация, несколько пакетов и END, краевые RGB-блоки, CRC BAD/LOST, метрики, несовпадающий эталон, отсутствие ложных пакетов в чистом шуме. Отдельный mock-тест проверяет однократную передачу, три END, нулевой буфер и очистку TX при ошибке.

Это не доказательство работы с конкретной прошивкой и USB-драйвером. В частности, не проверены на аппаратуре длительный дрейф частоты дискретизации, сильная многолучёвость, перегрузка АЦП и скорость обработки на вашем CPU. Здесь нет полноценной петли восстановления sample clock или адаптивного изменения модуляции. Если пакеты не распознаются, начните с BPSK, небольшого текста, преамбулы и низкой sample rate; проверьте URI/настройки/уровни и лог. CFO-поиск можно расширить до ±100 кГц ценой нагрузки CPU.

Официальные API ADI, использованные для аппаратного слоя: [Buffers](https://analogdevicesinc.github.io/pyadi-iio/buffers/index.html), [Pluto/ad936x](https://analogdevicesinc.github.io/pyadi-iio/devices/adi.ad936x.html), [Installation](https://analogdevicesinc.github.io/pyadi-iio/guides/quick.html).
