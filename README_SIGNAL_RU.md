# Структура сигнала и ожидаемая помехоустойчивость

Этот документ описывает **фактический формат текущей реализации** в `modem.py`, `radio.py` и `session.py`. Это однонесущий пакетный модем для ADALM-Pluto, а не OFDM. Цифры помехоустойчивости ниже — ориентиры для идеального канала и отправная точка для измерений, но не гарантия дальности или BER на реальной аппаратуре.

## 1. Сигнал от передачи до результата

Один цикл передатчика выглядит так:

```text
DATA 0 → DATA 1 → … → DATA N−1 → END → END → END → новый цикл с новым ID
```

RX начинает новую передачу только с пакета `seq=0`, собирает DATA-пакеты и завершает работу после первого принятого END. Три копии END повышают вероятность получить признак конца, но данные внутри одного цикла повторно не передаются. Пакеты из следующего цикла имеют другой ID и с предыдущим результатом не объединяются.

Каждый DATA- или END-кадр передаётся отдельным IQ-буфером:

```text
12 мс тишины
│
├─ необязательная преамбула: 256 BPSK-символов
├─ маркер: 64 фиксированных BPSK-бита
├─ 10 блоков защищённого BPSK-заголовка
├─ блоки тела в выбранной модуляции
│    каждый блок: [CP 16, если включён] [32 пилота] [128 символов]
└─ 12 мс тишины

после IQ-буфера: настраиваемая пауза TX, по умолчанию 20 мс
```

У всех частей сигнала `SPS = 8`, то есть один символ занимает 8 комплексных IQ-отсчётов. Формирующий RRC-фильтр не используется: линейные символы передаются прямоугольными импульсами.

## 2. Частота, sample rate и время

В интерфейсе задаётся частота центра полезного сигнала. Внутри программы LO Pluto устанавливается на `частота центра − Fs/4`, а цифровой перенос на `+Fs/4` возвращает сигнал в выбранный центр. Это сделано, чтобы DC-компенсация AD936x не подавляла несущую OOK.

| Параметр | 1 MS/s | 2 MS/s |
|---|---:|---:|
| Частота символов `Rs = Fs/8` | 125 ксимв/с | 250 ксимв/с |
| Один IQ-отсчёт | 1 мкс | 0,5 мкс |
| Один символ | 8 мкс | 4 мкс |
| Преамбула, 256 символов | 2,048 мс | 1,024 мс |
| Маркер, 64 символа | 0,512 мс | 0,256 мс |
| Блок без CP, 160 символов | 1,280 мс | 0,640 мс |
| Блок с CP, 176 символов | 1,408 мс | 0,704 мс |
| CP, 16 символов | 128 мкс | 64 мкс |

При переходе с 1 на 2 MS/s радиокадр становится вдвое короче, но полоса сигнала, нагрузка на USB и требуемая скорость обработки примерно удваиваются. При неизменной принятой мощности и спектральной плотности шума удвоение полосы обычно ухудшает `Eb/N0` примерно на 3 dB. Фиксированные защитные интервалы по 12 мс и пауза TX в миллисекундах при этом не сокращаются.

Для 2-FSK две частоты находятся относительно выбранного центра на `±Fs/8`: при 1 MS/s это `±125 кГц`, при 2 MS/s — `±250 кГц`. Поэтому 2-FSK занимает более широкую полосу, чем PSK/QAM с тем же `Rs`.

## 3. Преамбула, маркер, пилоты и CP

### Преамбула

Преамбула — известная псевдослучайная BPSK-последовательность из 256 символов перед каждым кадром. Она нужна для обнаружения начала кадра и даёт аналоговому тракту время установиться. В текущем детекторе первые 32 символа используются для грубого корреляционного поиска, первые 64 — для точной оценки частотного сдвига; после синхронизации RX пропускает всю преамбулу и переходит к маркеру.

С выключенной преамбулой поиск выполняется непосредственно по началу 64-битного маркера. Это экономит 2048 IQ-отсчётов, но на реальном радио обычно уменьшает запас синхронизации. Для первого запуска и нестабильного канала преамбулу лучше включать.

### Маркер

Маркер — постоянные 64 бита `d391c5a76e2b48f0`, переданные BPSK. Он обозначает начало заголовка и дополнительно уточняет CFO и фазу. Маркер не содержит длину, номер пакета или пользовательские данные.

### Пилоты

Перед каждыми 128 символами заголовка или тела передаются 32 известных BPSK-пилота. По ним RX для каждого блока отдельно оценивает:

- остаточный линейный набег фазы, то есть небольшой остаточный CFO;
- общую фазу созвездия;
- комплексный коэффициент усиления;
- при включённом CP для линейной модуляции — импульсную характеристику канала длиной 9 IQ-отсчётов.

Пилоты не несут пользовательских данных, не являются преамбулой и не исправляют битовые ошибки. Они только дают приёмнику известный эталон для коррекции текущего блока. Цена — 32 служебных символа на каждые 128 информационных, то есть 20% всех символов блока без учёта CP.

### Циклический префикс

При включённом CP перед каждым блоком копируются его последние 16 символов. RX удаляет эту копию. CP увеличивает блок со 160 до 176 символов, то есть добавляет 10% времени к блочной части кадра.

Для BPSK, QPSK, PSK/QAM и OOK при включённом CP используется частотная эквализация SC-FDE. Канал оценивается по пилотам моделью из 9 IQ-отсчётов. Поэтому физический CP равен 128 отсчётам, но текущий эквалайзер явно моделирует только задержки до 8 отсчётов относительно первого луча: около 8 мкс при 1 MS/s или 4 мкс при 2 MS/s. Для 2-FSK частотный эквалайзер не применяется; CP работает только как защитный интервал.

CP помогает при отражениях и межсимвольной интерференции, но почти не помогает против белого шума, постоянной помехи, неверной частоты или клиппинга. Заголовок декодируется по пилотам без SC-FDE, поэтому очень тяжёлый многолучевой канал всё равно может разрушить заголовок.

## 4. Заголовок пакета

Логический заголовок занимает 50 байт: 46 байт полей и 4 байта CRC32.

| Поле | Размер | Назначение |
|---|---:|---|
| Версия | 1 байт | Сейчас только версия 1 |
| Тип | 1 байт | `0` — текст, `1` — RGB |
| Модуляция | 1 байт | Индекс выбранной модуляции |
| Флаги | 1 байт | Преамбула, CP, END |
| ID передачи | 8 байт | Новый случайный ID каждого цикла |
| `seq` | 4 байта | Номер DATA-пакета; у END равен `total` |
| `total` | 4 байта | Ожидаемое число DATA-пакетов |
| `size` | 4 байта | Полный размер исходных данных |
| Ширина, высота | 2 + 2 байта | Размер RGB; для текста оба нулевые |
| `length` | 2 байта | Реальная длина данных в этом пакете |
| SHA-256 | 16 байт | Первые 16 байт хеша всего исходника |
| CRC32 заголовка | 4 байта | Проверка всех предыдущих полей |

Перед модуляцией заголовок отбеливается фиксированной псевдослучайной последовательностью. Затем каждый его бит повторяется трижды и передаётся BPSK; RX принимает решение большинством. Получается `50 × 8 × 3 = 1200` BPSK-символов. Они дополняются до 1280 символов и занимают ровно 10 блоков.

Тройное повторение — простейший FEC только для заголовка. Если вероятность независимой ошибки одного повтора равна `p`, после решения большинством она примерно равна `3p² − 2p³`. CRC32 затем отбрасывает заголовки, которые всё же декодировались неверно. При разных настройках модуляции, преамбулы или CP заголовок также отклоняется.

Отбеливание не является шифрованием и не добавляет помехоустойчивость: оно лишь убирает длинные однообразные последовательности.

## 5. Тело пакета и CRC

Один DATA-пакет содержит до 768 пользовательских байт:

- текст UTF-8 режется последовательными участками по 768 байт;
- изображение режется на блоки `16×16×3 = 768` RGB-байт;
- неполные краевые RGB-блоки дополняются нулями;
- последний текстовый пакет дополняется нулями до 768 байт только на физическом уровне.

К фиксированной области 768 байт добавляется CRC32 от **реальной** полезной части пакета. После этого все 772 байта отбеливаются последовательностью, зависящей от ID передачи и `seq`, и модулируются выбранным способом. END имеет `length=0`, но физически сохраняет такую же длину тела — это позволяет потоковому декодеру не доверять потенциально повреждённой длине.

У тела нет исправляющего кода, перемежения, ACK или повторной передачи пакета. CRC только обнаруживает ошибку:

- `GOOD` — заголовок и CRC тела верны;
- `CRC` — заголовок принят, но тело содержит ошибку;
- `LOST` — кадр/заголовок не обнаружен или не декодирован.

CRC-плохой RGB-блок всё равно показывается, поэтому на изображении видны повреждённые пиксели. Потерянный RGB-блок остаётся серым. В тексте потерянная область остаётся заполненной нулевыми байтами.

## 6. Модуляции, длина кадра и скорость

Все созвездия нормированы примерно к единичной средней энергии символа.

| Модуляция | Бит/символ | Реализация | Блоков тела | Кадр при 1 MS/s, CP выкл. | Кадр при 1 MS/s, CP вкл. |
|---|---:|---|---:|---:|---:|
| ASK / OOK | 1 | `0` или `√2`, когерентное решение | 49 | 78,080 мс | 85,632 мс |
| 2-FSK | 1 | Два ортогональных тона, решение по модулям корреляторов | 49 | 78,080 мс | 85,632 мс |
| BPSK | 1 | Две противоположные фазы | 49 | 78,080 мс | 85,632 мс |
| QPSK | 2 | 4 фазы, Gray-разметка | 25 | 47,360 мс | 51,840 мс |
| 8-PSK | 3 | 8 фаз, Gray-разметка | 17 | 37,120 мс | 40,576 мс |
| QAM-4 | 2 | Квадратное созвездие; геометрически эквивалентно QPSK | 25 | 47,360 мс | 51,840 мс |
| QAM-16 | 4 | Квадратная 4×4 QAM, Gray по I/Q | 13 | 32,000 мс | 34,944 мс |
| QAM-64 | 6 | Квадратная 8×8 QAM, Gray по I/Q | 9 | 26,880 мс | 29,312 мс |

В таблицу включена преамбула, но не включены две тишины по 12 мс и пауза TX. При 2 MS/s значения в двух последних столбцах делятся на два.

Для полного DATA-пакета 768 байт, с включённой преамбулой, выключенным CP, защитными интервалами `12 + 12 мс` и стандартной паузой TX `20 мс` приблизительная полезная скорость длинной передачи равна:

| Модуляция | 1 MS/s | 2 MS/s |
|---|---:|---:|
| OOK / 2-FSK / BPSK | 50,3 кбит/с | 74,0 кбит/с |
| QPSK / QAM-4 | 67,3 кбит/с | 90,8 кбит/с |
| 8-PSK | 75,7 кбит/с | 98,2 кбит/с |
| QAM-16 | 80,8 кбит/с | 102,4 кбит/с |
| QAM-64 | 86,7 кбит/с | 107,0 кбит/с |

Это скорость пользовательских байтов DATA-пакетов. Она не учитывает три END-кадра в конце цикла, поэтому для очень короткого сообщения средняя скорость заметно ниже. Большая часть времени быстрого режима сейчас уходит на фиксированные 24 мс тишины и паузу 20 мс, поэтому переход от QAM-16 к QAM-64 даёт меньший прирост, чем следует только из числа бит на символ.

## 7. Теоретическая помехоустойчивость

Ниже приведены приближённые пороги для независимых ошибок в идеальном канале AWGN, идеальной синхронизации и Gray-разметки. Для OOK предполагается когерентный амплитудный приём, для 2-FSK — ортогональный некогерентный приём. Это **не результат аппаратного измерения этого проекта**.

| Модуляция | `Eb/N0` для BER≈10⁻³ | `Eb/N0` для BER≈10⁻⁵ | Ориентир SNR в точке решений для BER≈10⁻⁵ |
|---|---:|---:|---:|
| BPSK | 6,8 dB | 9,6 dB | 9,6 dB |
| QPSK / QAM-4 | 6,8 dB | 9,6 dB | 12,6 dB |
| ASK / OOK | 9,8 dB | 12,6 dB | 12,6 dB |
| 8-PSK | ≈10,0 dB | ≈13,0 dB | ≈17,8 dB |
| QAM-16 | ≈10,5 dB | ≈13,4 dB | ≈19,4 dB |
| 2-FSK | ≈10,9 dB | ≈13,4 dB | Метрика RX напрямую не сопоставима |
| QAM-64 | ≈14,8 dB | ≈17,8 dB | ≈25,6 dB |

Связь для линейных созвездий: `Es/N0 ≈ Eb/N0 + 10·log10(бит/символ)`. Именно поэтому QPSK имеет тот же теоретический BER при одинаковом `Eb/N0`, что BPSK, но требует примерно на 3 dB большего SNR на символ при одинаковой энергии символа.

Показанный программой `SNR-оценка` вычисляется по ошибке точек решений относительно **заранее загруженного точного эталона**. В неё входят не только шум, но и остаточные CFO/фаза, многолучёвость, нелинейность и ошибка масштаба. Это не поверенный RF SNR и не `Eb/N0`. Для 2-FSK наблюдением является пара выходов корреляторов, поэтому его число нельзя напрямую сравнивать с PSK/QAM.

На стенде разумно закладывать минимум 3–8 dB запаса к идеальным порогам. Для очень малого числа CRC-плохих пакетов можно начинать со следующих ориентиров GUI, а затем измерять:

- BPSK: 13–16 dB;
- QPSK / QAM-4: 16–20 dB;
- 8-PSK: 21–25 dB;
- QAM-16: 23–28 dB;
- QAM-64: 30–35 dB.

Если есть клиппинг, заметный sample-clock drift, сильные отражения или помеха внутри полосы, даже больший SNR не гарантирует приём.

## 8. Почему для пакета нужен BER намного меньше 10⁻³

Полный пакет содержит 772 кодируемых байта, то есть 6176 бит вместе с CRC. Если грубо считать ошибки независимыми, вероятность полностью правильного тела равна:

```text
P(GOOD) ≈ (1 − BER)^6176
```

| BER | Вероятность GOOD полного пакета | PER только от битовых ошибок |
|---:|---:|---:|
| 10⁻³ | 0,207% | 99,793% |
| 10⁻⁴ | 53,922% | 46,078% |
| 10⁻⁵ | 94,011% | 5,989% |
| 10⁻⁶ | 99,384% | 0,616% |
| 10⁻⁷ | 99,938% | 0,062% |

Реальный PER может быть хуже из-за непринятой преамбулы, испорченного заголовка, потери IQ-буфера или END. Поэтому BER порядка `10⁻³` визуально кажется небольшим, но для 768-байтных пакетов почти всегда приводит к CRC BAD. Для PER заметно меньше 1% нужен BER примерно `10⁻⁶` или дополнительный FEC/повтор пакетов, которых в текущем теле нет.

BER в GUI считается только по принятым пакетам с валидным заголовком и только при точном совпадении эталона. LOST-пакеты в BER не входят, поэтому одновременно нужно смотреть `BER coverage` и итоговый PER.

## 9. Влияние разных типов помех

| Условие | Что происходит | Что помогает |
|---|---|---|
| Белый шум | Точки созвездия размываются, растут BER и CRC BAD | BPSK; меньшая скорость; больший уровень сигнала без клиппинга |
| Постоянная узкополосная помеха | Смещает/вращает точки или попадает в один тон FSK | Выбор чистой частоты по спектроанализатору; смена центра |
| Ошибка частоты генераторов | Корреляция и созвездие вращаются; вне диапазона поиска кадр становится LOST | Увеличить CFO range только до необходимого; прогреть генераторы |
| Медленный фазовый дрейф | Пилоты корректируют каждый блок | Больше запас SNR; BPSK/QPSK вместо 8-PSK/QAM-64 |
| Многолучёвость | Межсимвольная интерференция, деформация созвездия | CP + SC-FDE; меньшая скорость; изменение положения антенн |
| Клиппинг RX или нелинейность TX | QAM сжимается, ошибки остаются даже при сильном сигнале | Уменьшить RX gain/TX gain; использовать аттенюатор в кабеле |
| Импульсная помеха | Повреждает сразу много бит, весь пакет становится CRC BAD | Сейчас только смена частоты/экранирование; нужен interleaver/FEC для системного решения |
| Потери IQ из-за CPU/USB | Кусок потока исчезает, декодер сбрасывает поиск | 1 MS/s, меньший CFO range, шумовой порог, более быстрый CPU, очередь без переполнения |
| Слишком высокий squelch | Начало преамбулы отбрасывается, пакет LOST | Калибровать при выключенном TX и при необходимости снизить порог |

Шумовой порог и размер IQ-очереди не улучшают RF BER. Они уменьшают вычислительную нагрузку и риск программной потери отсчётов. Увеличение очереди только даёт процессору больше времени догнать поток; если средняя обработка постоянно медленнее поступления данных, очередь всё равно заполнится.

## 10. Рекомендуемые наборы параметров

### Максимальный шанс первого приёма

```text
BPSK, 1 MS/s, преамбула ON, CP ON при отражениях, CFO ±40 кГц
```

Сначала добейтесь нулевого клиппинга и нулевых потерь IQ. Если сигнал идёт по кабелю с аттенюатором и канал плоский, CP можно выключить. Расширять CFO до ±100 кГц стоит только если измеренный сдвиг действительно большой: число гипотез и нагрузка CPU растут.

### Компромисс скорости и устойчивости

```text
QPSK или QAM-4, 1 MS/s, преамбула ON, CP по условиям канала
```

QPSK и QAM-4 имеют одно и то же множество точек и практически одинаковую идеальную помехоустойчивость; отличается битовая разметка. Это наиболее безопасный следующий шаг после BPSK.

### Чистый кабельный стенд

```text
QAM-16 или QAM-64, 2 MS/s, преамбула ON, CP OFF
```

Обязателен подходящий аттенюатор между Pluto, отсутствие клиппинга и достаточный запас SNR. Для QAM-64 желательно видеть порядка 30 dB и выше по оценке точек решений, но окончательное решение принимать по PER.

### Канал с неизвестной фазой или нестабильной амплитудой

2-FSK не требует фазового решения полезных битов и имеет постоянную огибающую, но занимает широкую полосу и в идеальном AWGN уступает BPSK. OOK проста, однако примерно на 3 dB хуже BPSK в идеальном когерентном приёме и чувствительна к провалам амплитуды.

## 11. Как измерять результат на своей аппаратуре

1. Используйте на RX точно тот же исходный файл или текст, иначе BER и SNR недоступны.
2. Передавайте не меньше 100 полных пакетов: примерно 76,8 Кбайт текста или достаточно большое изображение.
3. Убедитесь, что нет сообщения о клиппинге и `потери IQ = 0`.
4. Для каждой комбинации параметров запишите итоговые BER, BER coverage, PER, SNR и CFO.
5. Повторите опыт несколько раз: один короткий запуск плохо характеризует редкие потери синхронизации.
6. Меняйте за один раз только один параметр: модуляцию, sample rate, CP, уровень или ослабление канала.
7. Для управляемого опыта используйте кабель и аттенюатор. При работе через антенны результат дополнительно зависит от разрешённой частоты, ориентации, отражений и внешнего эфира.

Главный критерий работоспособности — не красивое созвездие само по себе, а одновременно низкий итоговый PER, достаточное BER coverage, принятый END, отсутствие клиппинга и отсутствие программных потерь IQ.
